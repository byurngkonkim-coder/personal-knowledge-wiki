## 📌 요약 (Executive Summary)
- 본 소스는 하루 10시간 이상 클로드 코드를 실무에 기동하며 축적한 캐슬(아는 개발자)의 실전 중급 노하우 23가지를 정리하여, 비용 폭탄을 초래하는 비효율적 토큰 소모 구조를 타파하고 시스템 성능을 수배 이상 향상시키는 토큰 다이어트 매뉴얼을 다룬다.
- 점클로드 이그노어(.claudeignore) 파일 구축을 통한 탐색 배제, 매 메시지마다 자동 로드되는 클로드.md 파일의 200줄 축소 제약, 그리고 마스터 지침을 스킬 폴더로 쪼개는 분산 메모리 아키텍처 수립을 통해 기본 컨텍스트 공간을 콤팩트하게 보호한다.
- 메시지당 무려 38,500 토큰을 좀먹는 과도한 MCP 서버를 정리하는 4대 프로토콜과 툴서치 활성화 규칙을 정합하고, 단일 세션 대비 무려 10배 이상의 엄청난 토큰을 순간 소진하는 서브 에이전트의 난발 제약 요건(Haiku 지능 모델 위임)을 규명한다.

## 🧱 상세 분해 (Detailed Breakdown)

### 1. 프로젝트 파일 필터링 및 클로드.md (SOP 규칙)의 경량 설계 (방법 1 ~ 5)
- **핵심 논지**: 프로젝트 초기 가동 시 불필요한 대형 패키지의 자동 스캔을 전면 필터링 차단하고, 매 메시지 전송 시마다 0순위로 즉각 자동 열독되는 클로드.md 파일의 기본 토큰 소모 오버헤드를 물리적으로 경감해야 한다.
- **근거 및 데이터**:
  - **방법 1 (점클로드 이구노월 파일 만들기)**: 클로드 코드는 탐색을 개시할 때 `node_modules`나 `.next` 등 프로젝트 하위의 무수한 폴더들을 모두 정독하려고 하므로 토큰이 순식간에 녹아내림. 프로젝트 루트 디렉토리에 **`점클로드 이구노월 (또는 .claudeignore)`** 파일을 생성하여 배제할 파일/폴더를 기록함. 클로드 코드에게 `"이 프로젝트에서 점클로드 이그노에 넣을 파일이나 폴더들 추천해줘"`라고 쿼리하면 해당 프로젝트 기반으로 맞춤 가이드를 완벽히 추천 설계해 줌.
  - **방법 2 (클로드.md를 200줄 이하로 유지하기)**: 클로드.md(SOP) 파일은 세션 시작뿐만 아니라 매 대화 메시지 전송 시마다 자동으로 읽혀 컨텍스트를 과적하므로 **200줄 이내**로 콤팩트 다이어트를 이행해야 함. 축약 요령으로는 (1) 서수형 문장 제거, (2) 헤딩, 리스트, 테이블 형태로 정보 구조화, (3) 규칙 최소 단위로 축약, (4) 과도한 코드 예시 생략 등이 있으며, 200줄 돌파 시가 정리 타이밍임.
  - **방법 3 (상세 지식은 스킬로 분리)**: 클로드.md 본문 크기가 비대해지면, 범용 핵심 규칙만 클로드.md에 남기고 나머지 구체적 규칙(API 작성 가이드, DB 가이드 스킬, 배포 디플로이 가이드 등)은 `skills` 하부 스킬 폴더 파일로 쪼개 분리함. 스킬 파일은 필요할 때만 불러와 '온디맨드(On-demand)'로 동적 로드되므로 매 턴 기본 토큰 소모량이 대폭 절감됨.
  - **방법 4 (5가지 절약 규칙 추가)**: 클로드.md에 스스로 낭비를 제어하는 5대 규칙을 하드코딩 박아둠. (1) 이미 읽은 파일은 다시 확인하지 않는다, (2) 불필요한 도구 호출은 하지 않는다, (3) 가능한 도구 호출은 동시에 실행한다, (4) 스스줄 이상의 불필요한 출력은 서브 에이전트에게 위임한다 (수십 줄 이상의 불필요 출력 위임), (5) 사용자에게 이미 설정한 내용은 다시 반복하지 않는다. 특히 **1번과 5번** 수칙의 적용을 매우 강력히 권장함.
  - **방법 5 (이미 결정된 내용을 넣어두기)**: 아키텍처 결정 사항, 코딩 규칙(컨벤션), 빌드/테스트/배포 명령어 등 자주 바뀌지 않는 마스터 설정들을 클로드.md에 적치해 두면 불필요한 반복 타이핑 질의 프롬프트를 크게 경감할 수 있음.
- **주요 인용**: > "프로젝트 루트에 점클로 이그올 파일을 생성하고 뭐 이런 노드 모듈수나 넥스트 프로젝트 같은 경우에는 점넥스트 이런 것들을 넣어 주면 됩니다... 클로드.md는 MD는 세션을 시작할 때만 읽히는게 아니라 매시지만 읽기 때문에이 파일을 짧게 200줄 정도로 유지하는게 중요한데요"

### 2. 효율적 참조 범위 조율, 캐시 수명 관리 및 60% 지점 수동 컴팩션 (방법 6 ~ 10)
- **핵심 논지**: 대화 맥락이 임계점에 근접하여 추론 지능이 붕괴하는 것을 원천 차단하기 위해, 참조 용량을 줄이고 60% 사용 지점에서의 수동 컴팩션 및 익스텐티드 씽킹의 예산 통제를 이행해야 한다.
- **근거 및 데이터**:
  - **방법 6 (골뱅이로 파일 전체 참조를 지향/지양하기)**: 파일 크기가 **500줄 이하**일 때는 골뱅이(@) 기호로 전체 참조해도 되지만, **500줄이 넘어가는 순간** 필요한 특정 구간(함수나 클래스 단위)만 핀포인트 지정 참조해야 함. 만약 전체 파일이 **2,000줄**을 돌파한다면 파일 구조 설계 자체에 문제가 있으므로 컴포넌트를 쪼개야 함.
  - **방법 7 (60% 지점에 수동 컴팩션)**: 클로드 코드는 기본적으로 컨텍스트가 **95%** 꽉 차야 자동 콤팩션을 가동하는데, 이때는 이미 품질이 상당히 저하된 인지 장애 상태임. 따라서 `/context` 명령어로 사용률을 모니터링하다가 **60% 지점**에 도달했을 때 수동으로 콤팩션을 수렴함. 단순 실행이 아닌 보존할 구체적 요구조건을 함께 기재하는 방식을 추천함 (예: `슬래시 콤팩트 현재 구현 중인 로그인 기능의 핵심 로직과 발생한 에러 내역은 반드시 보존해줘`).
  - **방법 8 (자리 비우기 전에 압축하거나 클리어하기)**: 프롬프트 캐싱(Prompt Caching)은 5분 동안만 유효하게 동작함. **5분 이상** 자리를 비웠다가 복귀하면 캐시가 만료되어 모든 대화 맥락을 처음부터 다시 재처리하게 되어 사용량이 폭증하므로, 장시간 이탈 전에는 미리 `/compact`나 `/clear`를 실행해 세션을 정리함.
  - **방법 9 (쉘 명령어 긴 출력 주의)**: `git log` 전체 출력이나 전체 테스트 코드를 무지성 실행하면 수백 줄의 로깅 텍스트가 컨텍스트 윈도우로 쏟아져 들어옴. 특정 테스트만 조준 실행해 범위를 좁히거나, 훅(hook)을 가동해 출력 라인수를 head나 tail 명령어로 오토 상한 제어함.
  - **방법 10 (익스텐티드 씽킹 기능 제어)**: 깊은 추론 능력을 돕는 익스텐티드 씽킹(Extended Thinking)은 단순 파일 수정 시에도 보이지 않는 곳에서 무려 **3만 토큰**을 순식간에 소모하는 오버헤드를 유발함. 정교한 설계나 고난도 디버깅에만 기동하고 단순 작업 시에는 설정을 꺼두며, 컨피그 상에서 이 기능의 예산 한도를 제어해야 함.
- **주요 인용**: > "슬래시 컨텍스트 명령어로 사용률을 확인한 다음에 60% 정도가 됐을 때 수동으로 콤팩션을 실행을 해 주는 거죠... 익스텐티드 think킹 기능... 단순 파일 수정을 하는데도이 익스텐디드 think킹을 하는데 3만 토큰이 쓰일 수 있습니다"

### 3. MCP 도구의 오버헤드 통제와 분산 인덱싱 아키텍처 수립 (방법 11 ~ 15)
- **핵심 논지**: 외부 도구를 붙이는 무분별한 MCP 연동이 매번 기본 컨텍스트 예산을 고정 낭비하는 병목을 타파하기 위해, 서버 개수를 억제하고 툴 서치 옵션을 켜며 분산 인덱스 폴더 구조를 마련해야 한다.
- **근거 및 데이터**:
  - **방법 11 (MCP 서버 최소화)**: MCP 서버가 로드되면 매 대화 턴마다 도구 정의서 전체가 컨텍스트에 포함됨. 실측 통계로 플레이라이트(Playwright) MCP는 **17,600 토큰**, 슈퍼베이스(Supabase) MCP는 **2,900 토큰**을 소모하여, 두 서버를 켜두는 것만으로도 아무 말을 안 하고 엔터만 쳐도 매시지당 무려 **38,500 토큰**이 기본 고정 과적됨. `/mcp`로 점검해 정리할 것.
  - **방법 12 (MCP 툴 서치 옵션 설정)**: 수천 개의 무거운 외부 도구 중 필요한 항목만 실시간 기계 검색하여 불러오는 기능으로 **토큰을 무려 85% 절감**하고 선택 정확도도 높임. 기본값인 오토(Auto)는 컨텍스트의 10% 이상 점유 시에만 발동하므로, MCP 다중 기용 유저는 환경 설정에서 항상 활성 상태인 **`트루 (True)`**로 고정 설정해야 함.
  - **방법 13 (4단계로 MCP 서버 줄이기)**: (1) `settings.json` 내 `mcpServers` 항목 확인, (2) 도구 및 설명의 장황함 체크, (3) 예상 비용 추정 [수식: 도구 수 * 200 + 설명 글자수 / 4], (4) 가장 무겁고 오버헤드가 막중한 것부터 우선 정리.
  - **방법 14 (글로벌 레벨과 프로젝트 레벨 MCP 분리)**: 글로벌(전역) 설정에는 파일 시스템 MCP 딱 하나만 기입하고, 특정 프로젝트에 국한되는 전문 도구(Supabase, Playwright 등)는 프로젝트 로컬 레벨로 격리 배치하여 무거운 오토 로드를 차단함.
  - **방법 15 (분산 메모리 구조 만들기)**: 클로드.md를 세부 기획이 어디 박혀 있는지 알려주는 '인덱서(이정표)' 역할로만 가볍게 정의하고, 실제 상세 데이터는 `docs` 폴더 하부에 개별 마크다운 가이드로 격리시킴. API 수정 시에는 API 스펙 가이드만 콕 집어 로딩하게 제어하므로 루트 파일의 비대화를 완벽 가드함.
- **주요 인용**: > "mcp 서버를 연결하면 매시지마다 해당 서버의 모든 도구 정의가 컨텍스트 로드가 됩니다... 플레이라이트 MCP에는 17,600 토큰을 썼고 슈퍼베이스 MCP는 2900 토큰을 썼습니다... 아무 말도 안 하고 그냥 엔터만 쳐도 그냥 기본적으로 38,500 토큰이 매시지마다 쓰이는 겁니다"

### 4. 대규모 세션 인수인계, 플랜 게이트 및 서브 에이전트 다이어트 (방법 16 ~ 23)
- **핵심 논지**: 장기 작업에서 일관성이 끊기지 않도록 상태 보고서와 플랜 모드를 적극 활용하고, 토큰 소모량이 10배 폭증하는 서브 에이전트의 오남용을 타이트하게 조율 제어해야 한다.
- **근거 및 데이터**:
  - **방법 16 (대규모 작업 이어서 하기)**: 장기 프로젝트 기동 시 컨텍스트가 임계점에 도달하면, 메모리를 리셋하기 전 클로드에게 "지금까지의 완료 사항, 진행 중인 부분, 다음 실행 단계를 포함해 **`프로그램스.md (progress.md)`** 파일로 정리를 해줘"라고 명령해 상태 장부를 백업함. 이후 세션을 `/clear`로 청정 초기화한 뒤 새로 이어서 시작할 때 이 마스터 프로그램스 문서만 태깅 인계하여 맥락을 복구함.
  - **방법 17 (프로젝트에서 반복 파일 업로드하기)**: 클로드.ai 웹 UI 사용 시 동일한 대형 문서(PDF 등)를 매 세션마다 단순 반복 업로드하면 중복 토큰 과금이 발생함. 프로젝트(Project) 기능에 파일을 한 번 고정 연동해 두면 캐싱 처리가 유지되어 추가 토큰 낭비가 완벽 소거됨.
  - **방법 18 (플랜 모드 우선 활용)**: 잘못된 방향으로 코드를 길게 쓰고 이를 다시 지워 리팩토링하는 행위는 쓰는 토큰과 지우는 토큰 모두 2배로 지불하게 만듦. `Shift + Tab`을 두 번 클릭해 **`플랜 모드 (Plan Mode)`**에 진입한 후, 수정 파일 목록과 상세 아웃라인 기획서만 먼저 제출받아 검토 조율하고 명시적 최종 결재를 거쳐 실행 모드로 전향해야 리스크 비용을 원천 차단함.
  - **방법 19 (상태 표시줄 설정)**: 터미널 아래 바(Status Line)에 현재 가용 중인 인지 모델명과 실시간 컨텍스트 잔여 퍼센트 비율을 항상 가시적으로 상주 노출하여 최적의 수동 컴팩션 타이밍을 계측함.
  - **방법 20 (CCUSAGE 도구 사용)**: MPM(npm) 명령어로 설치 가능한 실시간 토큰 계측 소프트웨어로, 일일/월간/단일 세션별 실시간 과금 누적 퍼센트를 모니터링하여 원인 모를 토큰 누수를 즉각 추적 디버깅할 수 있게 도움 (`CCUCG` 표기 정합 포함).
  - **방법 21 (토큰 사용량 확인하는 세 가지 방법)**: (1) `/context` 명령을 통해 시스템 프롬프트, MCP 도구 명세서, 파일 메모리, 대화 텍스트 등 컴포넌트별 점량 실시간 체크, (2) 로컬 세션 로그 제어 JSON 파일 속의 `input_tokens`, `output_tokens` 필드 원형 직접 뜯어 확인, (3) 엔트로픽 공식 `token-counter` 웹툴 및 `클로다이저.앱` 에 내 `claude.md` 본문 내용을 직접 붙여넣어 바인딩 크기 검증.
  - **방법 22 (툴은 필요한 것만 연동)**: 서브 에이전트, 훅, MCP 등을 전역 공간에 무조건 과적 연동하지 않고 실제 필요에 의거해 로컬에 세팅함. 최근 2주 동안 실사용이 한 번도 관측되지 않은 가비지 툴은 완벽 제거.
  - **방법 23 (서브 에이전트 사용 주의)**: 서브 에이전트는 기동할 때마다 독립된 신규 환경을 구축하기 위해 전체 지시 컨텍스트를 새로 로드해야 하므로, 단일 세션 대비 **토큰을 최대 10배 이상 대량 소모**하는 주범임. 난발을 금하고 오직 탐색, 리서치, 20줄 이상의 단발성 고난도 분석 업무에만 격리 위임하며, 저렴하면서도 단순 연산을 똑똑히 완수해 내는 하이쿠(Haiku) 모델에 한해 서브 에이전트 연산을 위임하는 조합을 권장함.
- **주요 인용**: > "에이전트 워크 플로우는 단일 에이전트 세션보다 많으면 토큰을 열배 더 많이 사용하거든요 이게 왜 이렇게 토큰을 많이 쓰냐면 각 서브 에이전트가 깨어날 때마다 자신만의 전체 컨텍스트를 들고 다시 로드를 하기 때문입니다... 하이쿠 모델로 돌릴 수 있는 작업만 서브에트에게 맡기는 것을 추천드립니다"

### 5. 핵심 필수 추천 3선 가이드 요약
- **핵심 논지**: 23가지 다채로운 최적화 중에서 초보자가 당장 적용해야 할 압도적 가치의 마스터 실천 3선 목록을 공표한다.
- **근거 및 데이터**:
  - **추천 1 (점클로드 이구노월 파일 생성)**: 프로젝트 루트 디렉토리에 `.claudeignore` 파일을 단단히 배치하여 불필요한 노드 패키지와 대용량 이진 데이터 스캔을 원천 차단하는 공정을 최초 기동 시 필수로 이행할 것.
  - **추천 2 (클로드.md 다이어트)**: 헌법 문서의 분량이 200줄 장벽을 과적 돌파할 시, 상세 지침을 하부 docs 폴더 스킬 파일들로 영리하게 쪼개고 분할하여 매 턴 낭비되는 고정 토큰 누수를 가둘 것.
  - **추천 3 (안 쓰는 MCP 서버 칼같이 끄기)**: `/mcp` 목록 조회를 상시 켜두고, 최근 2주 동안 작업 전선에 기용되지 않은 무거운 도구(노션, 플레이라이트 등)를 단호하게 언마운트 끊어버릴 것.
- **주요 인용**: > "필수적인 거 딱 세 개만 골라봤어요 첫 번째는 점클로드 이그 파일 만드는 건데... 두 번째 클로점m 다이어트 하는 겁니다... 세 번째 안 쓰는 MCP 서버 정리하는 건데... 세 가지만 해도 효과가 매우 좋을 겁니다"

## 💡 주요 용어 (Key Terminology)
- **점클로드 이구노월 (.claudeignore / 점클로드 이그노어)**: 클로드 코드가 프로젝트 경로를 수집 및 스캔할 때 토큰을 탕진하게 만드는 `node_modules`나 `.next` 등의 거대 캐시 폴더를 추적망에서 영구 분리 배제하도록 강제하는 초기 환경 필터 설정 파일.
- **익스텐티드 씽킹 (Extended Thinking / 깊은 생각)**: AI 에이전트가 로직의 난이도를 스스로 판단하여 깊이 연산하도록 연산 자원을 집중 투자해 주는 기술이나, 단순한 텍스트 파일 수정 작업 시에도 약 3만 토큰을 순간 소소시키는 비용 폭탄을 유발할 수 있어 정밀 튜닝 시에만 선택 기동해야 하는 하이엔드 모드.
- **툴 서치 (Tool Search / 툴서치)**: 수백 수천 개의 복잡한 API 도구 전체를 매 턴마다 컨텍스트에 무조건 때려 박아 비용을 탕진하는 비효율을 깨고, 현재 사용자의 요구 텍스트에 가장 알맞은 핵심 도구만 실시간 똑똑하게 검색 추출하여 도구 오버헤드를 약 85% 가량 격감시키는 공식 MCP 절약 통제 기능.
- **분산 메모리 구조 (Decentralized Memory Structure)**: 루트 디렉토리의 `클로드.md` 파일에 사내의 무수한 코딩 룰, 배포 지침, DB 규칙까지 모두 적치하여 비대해지는 현상을 막기 위해, 마스터 클로드.md는 이정표(인덱스) 역할만 가볍게 수행하게 가두고 상세 가이드 원장들은 하부 docs 내 스킬 마크다운 파일로 세밀하게 격리 분산하는 수렴 아키텍처.
- **서브 에이전트 오버헤드 (Sub-agent overhead)**: 서브 에이전트가 호출될 때마다 완전히 깨끗하고 격리된 신입 사원 책상을 차리듯 자신의 전용 인스트럭션과 전체 컨텍스트 장부를 매번 처음부터 다시 패키지 로딩해야 하므로, 단일 세션 대비 토큰 소모량이 무려 10배 폭증하는 현상.
