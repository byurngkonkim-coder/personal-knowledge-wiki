# 📄 서브에이전트 모르면 클로드 코드 돈 버리는 겁니다 | EP.06 (Part: 전체)

## 📌 요약 (Executive Summary)
- 단일 대형 언어 모델(LLM) 한 명에게 재무제표 판독, 뉴스 감정 분석, 글로벌 업종 동향 파악을 한 공간에서 전부 지시하면 컨텍스트 윈도우 한계로 인해 과거의 핵심 수치를 기억하지 못하고 상실하는 현상이 발생한다 [1].
- 이를 해결하기 위해 사용자는 지휘자 역할의 `클로드.md` (사내 규정집)를 세우고, 실제 각 전문 도메인을 격리 병렬 처리하는 4인 서브 에이전트 팀(재무 분석가, 뉴스 감성 분석가, 업종 리서처, 공격적 투자 전략가)을 구축하여 협업을 조율하는 **"CEO 또는 감독의 마인드셋"**을 적용해야 한다 [1, 2].
- 4인 에이전트가 동시에 병렬 구동될 경우 단일 세션 대비 토큰 비용이 약 5배 증가하지만, 메인 컨텍스트 윈도우의 오염을 방지하고 각 독립 샌드박스 연산을 수행함으로써 **"SK 하이닉스 분석"** 한 줄만으로도 완결형 주식 투자 종합 분석 리포트를 자동으로 획득할 수 있다 [1, 3, 4].

### 1. 단일 AI 에이전트 가동의 한계와 컨텍스트 과부하 문제
- **핵심 논지**: 단일 AI 에이전트가 여러 도메인의 방대한 정보 분석을 한 번에 처리하려 하면 책상 위에 서류가 가득 쌓이듯 컨텍스트 공간이 포화되어 핵심 데이터를 상실하는 결함이 발생하므로, 전문가 팀(서브 에이전트)을 나눠 역할을 분장해야 한다 [1].
- **근거 및 데이터**:
  - **분석 정보 과부하**: 사용자가 "삼성전자 지금 살만해?"라고 질문하면, AI는 재무제표를 파악하고, 최근 한 달간 뉴스 기사 20개를 훑으며, 반도체 업종 전체 동향을 파악해 최종 의견을 도출해야 함 [1].
  - **기억 유실 현상**: 정보가 누적되어 단일 작업 공간이 포화되면 이전에 분석했던 핵심적인 수치를 모델이 중간에 망각함 [1].
  - **`클로드.md` (사내 규정집)의 한계**: `클로드.md`는 프로젝트 전체의 규칙과 배경 지식을 담은 사내 규정집으로서 훌륭하지만, 일하는 인력 자체가 단 1명인 경우 결국 사장이 혼자서 업무 매뉴얼 여러 권을 책상에 쌓아 두고 헤매는 모양새가 되어 품질 하락을 막지 못함 [1].
- **주요 인용**: > "재무 데이터를 잔뜩 읽고 뉴스를 쌓고 업종 분석을 쌓고 자 이러다 보면은 분석한 핵심 숫자를 나중에 얘가 까먹습니다... 매뉴얼이 아무리 많아도 일하는 사람은 사장님 한 명이고 책상 위에 서류가 계속 쌓이는 거죠" [1]

### 2. 서브 에이전트 기동을 통한 사장(CEO) 마인드셋의 정립
- **핵심 논지**: 비개발자는 단순 직원식 하부 코더 마인드셋에서 벗어나, 서브 에이전트라는 개별 직원을 채용하여 적재적소에 전권을 쪼개어 위임하는 최고경영자(CEO)의 지휘 통제 관점을 장착해야 한다 [2, 5, 6].

  - **CEO 비유**: 회사 CEO가 요구사항을 아주 러프하게 던지면 기획자, 개발자, QA가 분업해 기획, 코딩, 테스트, 배포를 순차 처리하여 성과를 내듯이, 사용자는 에이전트 팀원들을 지휘하는 역할을 담당해야 함 [2, 5, 6].

  - **에이전트 창조 명령어**: 클로드 코드 터미널 상에서 `/agent` 명령어를 치고 `create-new-agent` (또는 `create 뉴 에이전트`)를 선택함 [2].

    - *퍼스널 (Personal Level)*: 사용자의 PC 홈 디렉토리 전역에 상속되어 어떤 폴더 세션을 열든 즉각 동작할 수 있는 범용 직원 에이전트 설계 [2].

## 💡 주요 용어 (Key Terminology)
- **서브 에이전트 (Sub-agent)**: 클로드 코드 런타임 내에서 메인의 컨텍스트를 침범하여 오염시키지 않도록, 완전히 독립 격리된 연산 작업대를 신규로 분신 스폰하여 특정 도메인 업무(예: 재무, 번역, 린터)를 자율 처리하고 사장(메인 에이전트)에게 보고서 1장 요약본만 콤팩트하게 인수인계 보고해 주는 전문화 AI 가상 비서 [1, 12, 13].
- **에이전트 메모리 (Agent Memory)**: 단일 세션 엑시트 시 대화와 기억이 백지 초기화되는 고질 한계를 완벽히 타파하기 위해, 에이전트가 사용자와 호흡하며 누적 가공한 유효 지식과 사용자의 피드백을 자기 로컬 DB에 지속 보존 저장하여 세션 리셋 후에도 즉각 반영해 부활시키는 자율 학습 기억 장치 [7, 8, 14].
- **병렬 오케스트레이션 (Parallel Orchestration)**: 3~4인의 서브 에이전트들이 순차적으로 대기하며 시간을 낭비하는 낭비를 격파하고, 동시에 백그라운드에서 각개 전투식으로 재무 판독과 뉴스 분석을 병렬로 동시에 밀고 나가며 전체 작업 소요 스피드를 수직 상승시키는 멀티 에이전트 제어 기술 [3, 9, 12].
